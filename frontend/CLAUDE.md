## Project Overview

This is a React-based expense tracker application (frontend only) that connects to a backend API hosted at `https://expense-tracker-app-knl1.onrender.com`. The application allows users to:

- Register and login with authentication
- Select custom avatars using DiceBear API
- Track income and expense transactions
- View transactions in table or analytics/chart view
- Filter transactions by date range, frequency, and type
- Analyze spending by category with visual progress bars

## Development Commands

```bash
# Install dependencies
npm install

# Start development server (runs on http://localhost:3000)
npm start

# Run tests in watch mode
npm test

# Build for production
npm run build
```

## Architecture

### Backend API Integration

All API endpoints are defined in `src/utils/ApiRequest.js`:
- Authentication: register, login, setAvatar
- Transactions: add, get, update, delete

The backend host is configured in ApiRequest.js and can be toggled between production (Render.com) and localhost.

### Authentication Flow

1. User registers/logs in → Backend returns user object
2. User object stored in `localStorage` with key `"user"`
3. If `user.isAvatarImageSet === false`, user is redirected to `/setAvatar`
4. All authenticated pages check for `localStorage.getItem("user")` and redirect to `/login` if not found

### Routing Structure

- `/` - Home page (requires auth)
- `/login` - Login page
- `/register` - Register page
- `/setAvatar` - Avatar selection page (required after registration)

### State Management

No centralized state management (Redux/Context API). State is managed locally in components using:
- `localStorage` for user persistence
- Component state with useState hooks
- Props drilling for data sharing

### Key Components

**Pages:**
- `Home.js` - Main dashboard with transaction CRUD, filters, and view toggling
- `TableData.js` - Transaction table with inline edit/delete functionality
- `Analytics.js` - Visual analytics dashboard with circular and line progress bars
- `Login.js` & `Register.js` - Authentication forms with particle background
- `setAvatar.js` - Avatar selection using DiceBear API with random name generation

**Reusable Components:**
- `Header.js` - Navigation header
- `CircularProgressBar.js` - Circular percentage display
- `LineProgressBar.js` - Linear category progress bar
- `Spinner.js` - Loading indicator
- `Particle.js` - Background particle effects

### Transaction Categories

Fixed categories (defined in Home.js and Analytics.js):
- Groceries, Rent, Salary, Tip, Food, Medical, Utilities, Entertainment, Transportation, Other

Each category has an assigned color in Analytics.js for visualization.

### Data Fetching Pattern

Transactions are fetched in Home.js with dependencies on:
- `refresh` - toggled after add/edit/delete operations
- `frequency` - "7", "30", "365", or "custom"
- `type` - "all", "expense", or "credit"
- `startDate`/`endDate` - for custom date ranges

All transaction operations trigger `window.location.reload()` after success (see TableData.js).

### UI Libraries

- React Bootstrap - Layout and forms
- Material-UI (@mui) - Icons only
- react-toastify - Toast notifications
- react-datepicker - Date selection
- react-tsparticles - Background animations

### Common Patterns

**Toast Configuration:** Standardized `toastOptions` object used across components:
```javascript
{
  position: "bottom-right",
  autoClose: 2000,
  hideProgressBar: false,
  closeOnClick: true,
  pauseOnHover: false,
  draggable: true,
  progress: undefined,
  theme: "dark",
}
```

**Loading States:** Most async operations use a `loading` state to show Spinner component.

**Edit Pattern:** TableData.js stores the transaction being edited in `editingTransaction` state and opens a Bootstrap Modal for updates.

## Important Notes

- User authentication is entirely based on localStorage (no session/token expiration handling)
- The app uses `window.location.reload()` for state refresh after mutations (inefficient but simple)
- Date formatting uses moment.js library
- Avatar images are fetched from DiceBear API with unique random names generated by `unique-names-generator`
- Backend URL is hardcoded in ApiRequest.js - change there to switch between production and localhost
